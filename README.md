# 代码作者一致性核验

一个面向竞赛 C++ 代码的、可解释且可复现实验的作者风格对照系统。当前可用版本是完全在浏览器本地运行的工作台；实验管线用于逐步检验哪些指标真正有辨别力。

> 风格相容不能证明亲写，风格偏离不能证明 AI 或作弊。本项目不输出作弊概率，不支持据此直接处罚或做教育评价。

## 直接运行

零前端依赖、无需账号或 API Key。下载源码后，直接打开 `dist/index.html`。也可以在仓库根目录运行：

```sh
python -m http.server 8080 --directory dist
```

随后访问 `http://localhost:8080`。无需编译，不执行被分析的 C++ 代码。

## 使用流程

1. 点击载入合成示例，验证功能；合成示例不代表检测效果。
2. 导入自己的参考库 JSON 或批量 `.cpp`，填写作者和题目标识，检查同题/同源码副本。
3. 导入或粘贴一份待测代码。待测代码不会自动加入参考库。
4. 阅读逐项机会数、历史题数、行证据、模板排除范围及 token 相似度。
5. 导出 JSON 报告，保存分析参数、版本和证据。输入不足时不会给出来源判断。

导入的源码只在当前浏览器内处理。应用没有模型接口、上传接口、分析遥测或自动持久化；刷新页面会清空本次导入的数据。请主动导出需要保留的参考库和报告。

## 参考库格式

```json
{
  "metadata": {"title": "个人参考库", "description": "说明数据来源与确认程度"},
  "samples": [
    {"id": "sample-1", "name": "题目甲", "problemId": "contest:problem", "provenance": "来源说明", "code": "int main(){return 0;}"}
  ]
}
```

题目标识用于避免同题多版本虚增参考量。账号来源、第三方自述标签、教练确认亲写应分别记录，不能混为可信真值。不要将不同作者混入同一个人的画像。

## 实现与方法

- C++ 词法扫描，屏蔽注释和字符串内部的伪语法，保留原始行位置。
- 保守识别预处理指令、常见模板与简单入口分发壳；主体仍须人工检查。
- 12 项可解释习惯；每个特征同时记录匹配数和可观察机会数，无机会记为缺失。
- 按题目等权统计历史，避免长文件的标点数压倒其他题目。
- 原 token 与首现顺序标识符规范化 token 的 5-gram Jaccard 对照。
- 重复与改名克隆提示、同题排除、覆盖不足提示。

这是词法近似，不是 Clang AST、控制流图或语义绑定分析。标识符规范化不是作用域感知的 α 归一化。没有训练通用 AI 检测器，也没有验证可用的低误报阈值。

详细定义、局限及后续实验见 [方法与验证说明](方法与验证说明.md)。

## 工程测试

Node.js 18 或以上：

```sh
node --test tests/*.test.cjs
```

工程测试检查提取器和数据流程是否符合定义；通过并不等于可以识别 AI。

Python实验管线及固定依赖、题目/时间分割、历史量对照见 [实验说明](experiments/README.md)。CST结构提取见 [结构特征说明](experiments/STRUCTURAL_FEATURES.md)。已有公开数据来源诊断及失败结果见 [首轮诊断结果](experiments/AI_DIAGNOSTIC_RESULTS.md)，该诊断不具有作者或题目隔离。

```sh
python -m pip install -r experiments/requirements.txt -r experiments/requirements-structural.txt
python -m unittest discover -s tests -p 'test_*.py' -v
```

## 隐私与数据

公开仓库只包含实现、测试和合成样例。个人历史源码、独立测试原文、浏览器会话、密钥和平台数据集不进入仓库。研究数据应保存在仓库之外，并遵守其自身许可。请不要把私人参考库提交到 Git。

## 开发方向

1. 固定并审计提取器和模板边界；保存版本与失败案例。
2. 收集具有作者、题目及来源标识的公开数据，区分缺失时间与真实时间分割。
3. 用独立开发集固定规则，跨题/跨时间测试误报、异作者识别与覆盖率。
4. 在明确许可和可信标签条件下增加 AI 仿写及轻度改写对照。
5. 只有经过独立评估的组件才提升为正式判别功能。

本仓库沿用仓库原有 Apache-2.0 许可；外部数据、论文和第三方模型各自适用原许可，不被该许可覆盖。

## 公开数据获取与复现

[CodeNet 获取与准备](experiments/data/README.md)提供官方来源下载、摘要校验、安全流式读取、冻结的40/100账户选样及聚合统计脚本；[数据卡](experiments/data/DATASET_CARD.md)说明许可、时间跨度、长度分布与选择偏差。原始数据必须放在仓库外，本仓库不包含源码数据或逐账户清单。

离线合成数据管线测试：`python -m unittest discover -s experiments/data/tests -v`。完整数据准备约需12 GB可用空间，不是运行浏览器工作台的前提。评分与分割实验见[实验说明](experiments/README.md)。

## 已完成的研究检查点

- [注册内作者矩阵](experiments/CODENET_RESULTS.md)：40个公开账号、1811份C++，完整报告12组配置及空分区失败。
- [未见作者迁移](experiments/AUTHOR_TRANSFER_RESULTS.md)：100账号4549份，40开发/20校准/40最终测试作者。严格时间下注册与评分覆盖不足，不能据此声称40名学生可靠有效。
- [一次性盲仿写](experiments/GENERATED_STRESS_RESULTS.md)：三例可构造，一例不可构造；固定阈值，完整报告标记与拒判，样本极少。
- [格式与改名诊断](experiments/ROBUSTNESS_RESULTS.md)：表示敏感性不等于检测效果，接受门槛导致的不变量不能充当独立稳健性证明；附[后验工程修正记录](experiments/ROBUSTNESS_CORRECTIONS.md)。
- [可选预训练提取器](experiments/PRETRAINED_EMBEDDINGS.md)：固定官方C++模型，离线CPU推理工程验证完成；不在浏览器中加载，真实迁移实验仍进行中。
- [验收与学生前瞻方案](docs/ACCEPTANCE_AND_FIELD_PROTOCOL.md)：区分研究交付、浏览器验收及未来课堂验证，后两项尚未完成。

详细进度、精确测试数、远端检查及恢复方法见 [PROGRESS.md](PROGRESS.md)。浏览器交互仍受正常登录要求阻塞；Node模拟DOM测试不替代真实浏览器验收。
